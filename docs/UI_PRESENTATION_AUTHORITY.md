# Matrix UI Presentation Authority

## 1. Scope and precedence

This file specifies visual ownership boundaries for the materially used Qt/PySide6 presentation families in Matrix3. It is presentation-only and is subordinate to `AGENTS.md`, `docs/LAW_Smart_Student_Allocation_v3.0.md`, `docs/Technical_SSoT_Smart_Student_Allocation_v3.0-TECH.md`, and the other repository domain authorities. It does not change domain, task, persistence, CLI, Core, or Infra behavior.

This is a specification, not executable drift prevention. Runtime cleanup and invariant tests belong to later phases.

## 2. Native / Styled / Hybrid definitions

- **STYLED** — the Matrix presentation system owns the visible surface and every geometry-sharing visual subcontrol needed for a coherent component. Qt retains behavior, input, accessibility, model/view, focus mechanics, and other widget semantics.
- **NATIVE** — the active Qt/platform style owns the component's visible geometry. Matrix may supply content and non-conflicting application palette/typography, but must not partially repaint geometry-bearing subcontrols.
- **HYBRID** — ownership is explicitly partitioned along a stable boundary that does not give one geometry-sharing surface two incompatible owners. The registry states both sides and the forbidden crossing.

Native behavior is not native appearance. A control may remain behaviorally native while its presentation is Matrix-owned.

## 3. Global ownership invariants

1. **A single geometry-sharing control must not have two incompatible visual owners.**
2. If Matrix styles a control's outer geometry, any subcontrol that interrupts or shares that geometry is Matrix-owned too, unless the registry defines a stable HYBRID boundary.
3. A self-contained native indicator may remain Qt-owned when Matrix does not draw a competing shell around that indicator.
4. `Fusion` is the configured Qt base style. `QPalette` supplies theme-compatible native colors; `styles.qss` is the centralized Matrix styling surface. No custom `QStyle`/`QProxyStyle` is a presentation authority at this repository identity.
5. Local `setStyleSheet()` or `setFont()` calls do not create a new ownership model. They must remain within the registry boundary and must not establish a second geometry owner.
6. LTR and RTL use the same ownership classification. A STYLED geometry-bearing subcontrol must be specified in a direction-safe way rather than by one-direction offsets.

## 5. Forbidden partial-styling patterns

- Custom outer `QComboBox` border/background/radius while `::drop-down` or `::down-arrow` remains an unrelated Fusion visual owner.
- Styling only one geometry-bearing piece of a native `QScrollBar`, tree branch/indicator, or other complex native control.
- Giving a `QFrame` both a visible native frame shape and a competing Matrix border/radius on the same instance.
- Styling `QCheckBox::indicator` piecemeal while the indicator remains classified Qt-native.
- Per-widget `setStyleSheet()` that establishes a second visual contract for a centrally governed family.
- Treating Qt behavior ownership as a reason to leave a geometry-sharing visual subcontrol native inside a STYLED shell.
- Using LTR-only offsets to position a STYLED complex-control subcontrol.

## 6. Consumption rules for later UI work

1. Look up the family here before changing its appearance.
2. For **STYLED**, use the existing Matrix theme/QSS authority and cover every relevant geometry-sharing subcontrol and state; keep Qt behavior intact.
3. For **NATIVE**, do not add targeted geometry QSS. Palette/typography integration is allowed only when it does not create a second visual owner.
4. For **HYBRID**, change only the Matrix-owned side named in the registry. Expanding that boundary requires updating this authority before implementation.
5. A materially introduced Qt family not in the registry requires an authority decision before bespoke styling is added.
6. Dormant QSS selectors are not permission to use a family as styled. Actual family use must agree with this registry.
7. A local stylesheet may refine an already Matrix-owned non-geometry property, but cannot override this file's owner classification.
8. This document specifies ownership; later code/test phases must separately implement and verify conformance.

### Current `QComboBox` evidence

The current bytes do have a split visual owner:

- `app/ui/styles.qss` customizes `QComboBox` background, border, radius, padding, hover/focus/disabled state and the popup `QAbstractItemView`.
- The same QSS explicitly says the drop-down/arrow stays Fusion-native and contains no `QComboBox::drop-down` rule.
- `app/ui/theme.py` configures `app.setStyle("Fusion")` before applying the Matrix palette and QSS.
- `tests/ui/test_uiux_method_locks.py` asserts that `QComboBox::drop-down` is absent and queries the arrow rectangle through `QStyle.CC_ComboBox` / `SC_ComboBoxArrow`.
- `app/ui/main_window_base.py` materially uses both the theme selector and editable manager `QComboBox` controls; `app/ui/preferences/language_dialog.py` also uses `QComboBox`.

Therefore the **current implementation state** is `Matrix outer/popup + Fusion drop-down/arrow`. The **specified authority classification** is `STYLED`, so a later remediation phase must either bring all geometry-sharing ComboBox presentation under the Matrix contract or first amend this authority. Phase 0 performs neither runtime change.
