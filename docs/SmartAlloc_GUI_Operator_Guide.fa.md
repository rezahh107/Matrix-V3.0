# راهنمای اپراتور SmartAlloc GUI

> **منبع حقیقت قوانین تخصیص (LAW v3.0 / Technical SSoT v3.0):** این سند راهنما/تاریخچه است؛ تمام قواعد ثابت (کلیدهای join، رتبه‌بندی، انواع منتور/دانش‌آموز، گیت ظرفیت، trace و ...) فقط در `docs/LAW_Smart_Student_Allocation_v3.0.md` و `docs/Technical_SSoT_Smart_Student_Allocation_v3.0-TECH.md` معتبرند. در صورت هر تعارض، محتوای این دو فایل حاکم است و نکات قدیمی این سند به‌عنوان LEGACY خوانده شوند.

## مقدمه
SmartAlloc به اپراتورها کمک می‌کند ماتریس احراز صلاحیت دانش‌آموزان و فرآیند تخصیص به پشتیبان‌ها را مطابق Policy واحد تولید کنند و خروجی ImportToSabt را برای ثبت نهایی بسازند. این راهنما مراحل روزمره GUI را به زبان ساده توضیح می‌دهد.

> **وضعیت Rule Engine:** رابط گرافیکی Rule Engine از فضای عادی کاربر بازنشسته شده است. Backend و فرمان CLI `rule-engine` برای نیازهای فنی/سازگاری عمداً حفظ شده‌اند. نبودن آن در GUI به معنی حذف backend نیست.

## پیش‌نیازها
- **سیستم‌عامل:** ویندوز 10 یا 11 نسخه 64بیتی با آخرین به‌روزرسانی‌ها.
- **کتابخانه‌های سیستمی:** نصب بسته‌های Microsoft Visual C++ Redistributable 2015-2022. در بیشتر سیستم‌ها وجود دارند؛ اگر برنامه اجرا نشد، از وب‌سایت رسمی مایکروسافت نصب کنید.
- **مسیر پشتیبانی‌شده:** پوشهٔ کامل سورس پروژه (شامل `pyproject.toml`، `uv.lock` و `.python-version`) و ابزار `uv` در PATH. نسخهٔ Python موردنیاز پروژه در `.python-version` مشخص است و `uv` محیط قفل‌شده را مدیریت می‌کند.
- **محدودیت تحویل:** بستهٔ PyInstaller، فایل EXE مستقل و نصب‌کننده جزو اهداف پشتیبانی‌شدهٔ فعلی Matrix نیستند؛ دستورالعمل‌های قدیمی بسته‌بندی مسیر پیشنهادی اپراتور محسوب نمی‌شوند.

## نحوه اجرای برنامه

پس از نصب `uv`، از ریشهٔ سورس پروژه در PowerShell فرمان‌های زیر را اجرا کنید:

```bash
uv sync --locked
uv run --locked python -m app.main
```

این فرمان‌ها مسیر اجرای مستندشده‌اند؛ موفقیت راه‌اندازی در یک Windows تمیز و تجربهٔ عملی اپراتور هنوز به اعتبارسنجی مستقل نیاز دارند.

## معرفی مسیرهای اصلی رابط کاربری

### «ساخت ماتریس» (Build Matrix)
- ورودی اجرای Build: فایل Inspactor و خروجی مقصد؛ School/GroupCode reference پیش از اجرا از Database به LocalDatabase وارد/به‌روزرسانی می‌شود و Build آن را فقط از DB می‌خواند.
- خروجی: فایل ماتریس اهلیت که مبنای مراحل بعدی است.
- چه زمانی استفاده می‌شود: ابتدای سال تحصیلی یا هر زمان داده‌های مرجع اصلاح شده‌اند.

### «تخصیص» (Allocate)
- ورودی‌ها: فایل دانش‌آموزان، استخر منتورها، روسترها و سال/ترم موردنظر.
- مراحل پیشنهادی:
  1. فایل دانش‌آموزان و mentor pool را انتخاب کنید.
  2. در صورت نیاز روسترهای قبلی/جاری و پارامترهای مرتبط را تنظیم کنید.
  3. اجرای Allocate را شروع کنید.
  4. خروجی تخصیص و ImportToSabt را بررسی کنید.
- مسیر ریشه خروجی از Settings قابل تنظیم است و GUI برای runهای Build/Allocate پوشه خروجی run ایجاد می‌کند.

### «Database»
- School و GroupCode reference از Database مدیریت می‌شوند.
- اگر داده مرجع تغییر کرده است، ابتدا آن را در Database به‌روزرسانی کنید و سپس Build/Allocate را اجرا کنید.

### «Explain»
- برای مشاهده اطلاعات توضیحی/Trace مرتبط با تصمیمات و کمک به بررسی فنی استفاده می‌شود.

## Diagnostics & Advanced Tools — ابزارهای خطایابی و پیشرفته

این بخش در Settings قرار دارد و هشت قابلیت عمداً حفظ‌شده را در سه گروه نشان می‌دهد:

1. **ابزارهای خطایابی و مشاهده:** Trace Debug Sheets، Mentor Pipeline Trace، Pool Governance Trace، Bucket Trace، Trace Sheet Export.
2. **تحلیل:** History Metrics.
3. **اعتبارسنجی و رفتار پیشرفته:** QA Pool Coverage Rules، Use Join Buckets.

هر گزینه توضیح کوتاه، برچسب اثر رفتاری و دکمه `Full Guide / راهنمای کامل` دارد. راهنمای کامل فارسی و English بدون تغییر زبان کل برنامه در دسترس است.

دو هشدار مهم:

- **QA Pool Coverage Rules** فقط diagnostic نیست و ممکن است PASS/FAIL اعتبارسنجی QA را تغییر دهد.
- **Use Join Buckets** گزینه الگوریتمی/کارایی است و مسیر اجرای جست‌وجوی کاندیدها را تغییر می‌دهد؛ کاربر عادی باید آن را بدون دلیل فنی مشخص خاموش بگذارد.

برای جزئیات فنی، نام دقیق sheetها، محدودیت‌ها و راهنمای تفسیر به `docs/DEVELOPER_DIAGNOSTICS.md` مراجعه کنید.

### گروه «خروجی Sabt (ImportToSabt)»
- **Sabt Export Profile (الزامی برای Allocate):** فایل Excel دارای شیت `Sheet1` و نگاشت معتبر ستون‌های Sabt را از مرجع مجاز سازمان تهیه و با «فایل پروفایل Sabt» انتخاب کنید. این فایل با `sabt_template` متفاوت است. فایل تاریخی `docs/Report (4).xlsx` در بستهٔ تمیز uv وجود ندارد و نباید فایل خصوصی را به Git، CI یا پیوست عمومی اضافه کنید. اگر در کپی توسعهٔ کامل وجود داشته باشد، برنامه ممکن است آن را پیشنهاد کند؛ در بستهٔ توزیع تمیز باید صریحاً فایل مجاز را انتخاب کنید.
- **sabt_output:** مسیر فایل خروجی ImportToSabt؛ برای تولید آن در اجرای Allocate مسیر معتبر وارد کنید.
- **sabt_config:** فایل JSON تنظیمات صادرکننده؛ اگر خالی بماند، Config موجود در سورس استفاده می‌شود.
- **sabt_template (اختیاری):** قالب *Workbook* برای Sheet2/Summary/Errors، جدا از Profile نگاشت. اگر این مسیر خالی و خروجی Sabt تنظیم شده باشد، GUI پس از تأیید پیش‌بررسی یک زیرپوشهٔ یکتا در مقصد می‌سازد و فایل قالب حداقلی `sabt-template.xlsx` را آنجا ایجاد می‌کند؛ هیچ فایل همنام موجودی را به‌عنوان قالب خودکار تغییر نمی‌دهد. قالب صریح انتخاب‌شده مطابق قرارداد موجود مصرف می‌شود و نباید همان مسیر فایل خروجی باشد. قالب خودکار جایگزین تأیید سازمانیِ قالب واقعی نیست.
- پس از تکمیل، فایل‌های تخصیص، `*_validation.xlsx`، Trace در صورت فعال‌بودن، و فایل Sabt را در Excel بازبینی کنید. قبل از جایگزینی فایل مهم نسخه قبلی را نگه دارید. نتایج تولیدشده از Profile ساختگی صرفاً اثبات اجرای نرم‌افزار هستند، نه سازگاری عملیاتی با Sabt.

## سناریوهای روزمره

### سناریوی شروع سال تحصیلی
1. داده‌های مرجع School/GroupCode را در Database بررسی/به‌روزرسانی کنید.
2. Inspactor را انتخاب و Build Matrix را اجرا کنید.
3. داده دانش‌آموزان و mentor pool را در Allocate وارد کنید.
4. تخصیص را اجرا و خروجی‌ها را بررسی کنید.
5. در صورت نیاز خروجی ImportToSabt را تولید کنید.
6. فقط در صورت وجود یک سؤال مشخص عیب‌یابی، قابلیت مرتبط Diagnostics & Advanced Tools را روشن کنید.

### سناریوی به‌روزرسانی میانه سال
1. لیست دانش‌آموزان/منتورهای جدید را دریافت کنید.
2. اگر داده مرجع تغییر کرده، Database و سپس Build را به‌روز کنید؛ در غیر این صورت از baseline معتبر موجود استفاده کنید.
3. اجرای جدید را از مسیر Allocate انجام دهید.
4. خروجی جدید را قبل از جایگزینی نسخه قبلی بررسی کنید.

## مدیریت خطا
- **ورودی اشتباه یا بدون ستون لازم:** پیام خطا را بخوانید، فایل را اصلاح و دوباره اجرا کنید.
- **کمبود ظرفیت یا داده مشکوک:** QA/trace مناسب را بررسی کنید؛ هر diagnostic را فقط برای سؤال مشخص فعال کنید.
- **خطای غیرمنتظره:** جزئیات در logهای برنامه ذخیره می‌شود؛ هنگام گزارش خطا مسیر/log مرتبط را ارائه کنید.

## نکات پایانی
- فایل `config/policy.json` و سایر Policyها توسط authorityهای دامنه نگه‌داری می‌شوند؛ برای رفع مشکل ظاهری UI/diagnostics، semantics آن‌ها را تغییر ندهید.
- OFF بودن یک قابلیت تشخیصی به معنی dead code بودن آن نیست.
- خاموش‌کردن یک setting artifactهای قبلاً تولیدشده را حذف نمی‌کند.
